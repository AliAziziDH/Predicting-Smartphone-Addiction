PART 1: THE JULES SETUP SCRIPT ARCHITECTURE & SNAPSHOTTING
--------------------------------------------------------------------------------
Google Jules clones the target repository into an isolated, secure Google Cloud
VM to execute tasks. To avoid downloading dependencies and compiling solvers
on every run, Jules uses "Setup Scripts" and "Environment Snapshotting".

A Setup Script is a Bash script executed at the initialization of the VM.
After a successful test run, Jules snapshots the VM, allowing future runs to
boot instantly with all system-level dependencies pre-configured.

1. BPRINT FOR PYOMO / OPERATIONS RESEARCH REPOSITORIES (Sharif University Projects)
   OR repositories require native mathematical solvers (e.g., COIN-OR CBC, GLPK)
   that must be installed via the Debian package manager (apt-get) on the cloud VM.

   Paste this exact script into the "Setup Script" box under Jules Repo Settings:
   ```bash
   #!/bin/bash
   echo "===> Bootstrapping Operations Research Environment <==="
   # 1. Update package lists and install native mathematical solvers
   sudo apt-get update && sudo apt-get install -y \
       coinor-cbc \
       glpk-utils \
       libglpk-dev \
       gfortran \
       build-essential

   # 2. Verify solver installations
   which cbc || echo "WARNING: CBC solver not found in PATH"
   which glpsol || echo "WARNING: GLPK solver not found in PATH"

   # 3. Install Python-level dependencies
   if [ -f requirements.txt ]; then
       echo "Installing requirements.txt..."
       pip install --upgrade pip
       pip install -r requirements.txt
   else
       echo "No requirements.txt found. Installing baseline optimization stack..."
       pip install pyomo scipy numpy pandas openpyxl pytest
   fi
   echo "===> OR Environment Setup Complete! <==="
   ```

2. BPRINT FOR PURE MACHINE LEARNING & KAGGLE REPOSITORIES
   Kaggle and ML repos should bypass heavy native-solver compilation to keep
   the VM snapshot incredibly lightweight and optimize the token footprint.

   Paste this exact script into the "Setup Script" box under Jules Repo Settings:
   ```bash
   #!/bin/bash
   echo "===> Bootstrapping Machine Learning Environment <==="
   # 1. Update pip to the latest version
   pip install --upgrade pip

   # 2. Install ML-centric packages using pip
   if [ -f requirements.txt ]; then
       echo "Installing requirements.txt..."
       pip install -r requirements.txt
   else
       echo "No requirements.txt found. Installing baseline ML/Data Science stack..."
       pip install numpy pandas scikit-learn lightgbm xgboost optuna pytest
   fi
   echo "===> ML Environment Setup Complete! <==="
   ```

3. HOW TO TRIGGER SNAPSHOTTING:
   - Paste the appropriate script into the "Setup script" box in the Jules Web UI (jules.google.com).
   - Click "Run and snapshot".
   - Jules will provision the VM, run the script, verify the exit code is 0, and save an image snapshot.
   - Subsequent tasks will start instantly, bypassing the install phase.

PART 2: THE REPOSITORY-LEVEL AGENTS.md SPECIFICATION
--------------------------------------------------------------------------------
Jules automatically looks for a file named "AGENTS.md" in the root of the
repository. This file acts as the "USB-C Port" of the repository, providing
Jules, Claude Code, and other agentic clients with strict structural, execution,
and testing instructions.

Create a file named "AGENTS.md" in the root of your repository and paste the 
following template (customized to your project name):

```markdown
# 📄 AGENTS.md: Repository Capabilities, Architecture, and Agent Guidelines

This repository is optimized for agentic development (Google Jules, Claude Code).
All agents operating on this repository MUST strictly adhere to the standards, 
architecture, and execution rules defined in this document.

---

## 🎯 Project Overview & Context
- **Project Name:** [Insert Project Name, e.g., supply-chain-optimization]
- **Target Domain:** Decision Intelligence / Operations Research / Machine Learning
- **Principal Architect:** Ali Azizi (Sharif University MSc Optimization Methods)
- **Primary Tech Stack:** Python 3.11+, Pyomo (Mathematical Modeling), Pandas, Scikit-Learn, Pytest

---

## 🏛️ System Architecture & Separation of Concerns (SoC)
To prevent agent drift and maintain modular, clean code, this repository strictly
enforces a separation of concerns. Do not mix business/mathematical logic with the 
presentation/UI layer:

1. **Analytical Core (`src/model/`):**
   - Must contain pure mathematical formulations and data-science pipelines.
   - All Pyomo models MUST be declared in `src/model/formulation.py`.
   - Set optimization parameters as mutable (`mutable=True`) to allow dynamic
     scenario updating and sensitivity analysis.
   - Solver invocation and configuration belong strictly in `src/model/solver.py`.
   - The analytical core must remain 100% headless (no Streamlit, no Matplotlib UI).

2. **Presentation Layer (`src/ui/`):**
   - Streamlit dashboards and Plotly interactive visualizations belong in `src/ui/app.py`.
   - The UI must import the formulation and solver classes from `src/model/` to run optimization.
   - Always use a clean, dark-themed dashboard design with glassmorphism KPI cards.

3. **Data Loading (`src/utils/`):**
   - All dataset loading, preprocessing, and directory-safe path resolving
     belong in `src/utils/data_loader.py`.
   - Never use absolute, hardcoded local paths. Always resolve paths relative to
     the repository root dynamically.

---

## 🔌 Stateless MCP 2.0 & Token Economy Directives
- **Model Context Protocol (Spec 2026-07-28):** All tools and agent interactions 
  use stateless execution.
- **Tools Tax Elimination (Tool Attention):** Do not load raw JSON Schemas of all
  tools. Utilize compact tool summaries (<60 tokens) for initial discovery.
- **Code Execution on MCP:** Write compact, self-contained Python scripts that
  execute local tool chains in a sandboxed executor, reducing input token
  overhead by 78.5% and costs by 70%.
- **Explicit Handles:** Return explicit resource identifiers (e.g., `dataset_id`,
  `model_id`) in tool outputs and require the agent to pass them back in later
  calls, keeping the system serverless-friendly.

---

## 🧪 Testing and Verification Suite
Jules is an edit-test-repair agent. It cannot verify code changes without a 
deterministic pass/fail check.
- **Test Runner:** Always use `pytest` as the verification engine.
- **Execution Command:** Run `pytest -v` from the repository root to verify edits.
- **Standard Assertions:** 
  - For ML: Assert model shape, input coverage, and metric functions (e.g., RMSLE).
  - For Pyomo: Assert solver status is `TerminationCondition.optimal`, assert binary
    variable integrity, and assert capacity/demand bounds.

---

## 🛡️ Repository Etiquette & Pull Request Safety
- **Draft PRs:** Always open Pull Requests as Drafts by default. Merges require 
  explicit human-in-the-loop review.
- **Mentions Only:** Jules only responds to review comments that explicitly 
  mention `@jules` to preserve token quotas.
```

PART 3: UNIT TEST TEMPLATES (pytest verification)
--------------------------------------------------------------------------------
Jules requires a test suite to debug itself. Always include a `tests/` directory
with a verification file. Below are the two standard layouts for Ali's repos:

1. FOR PYOMO / OPERATIONS RESEARCH (tests/test_formulation.py)
   ```python
   import pytest
   from pyomo.environ import SolverFactory, TerminationCondition
   from src.model.formulation import LogisticsModel

   def test_optimization_solver_integration():
       # Initialize the Pyomo formulation
       model_instance = LogisticsModel()
       model = model_instance.build_model()
       
       # Attempt to solve using CBC
       solver = SolverFactory('cbc')
       if not solver.available():
           pytest.skip("CBC solver is not available on this system")
           
       results = solver.solve(model)
       
       # Enforce strict mathematical assertions
       assert results.solver.status == results.solver.Status.ok
       assert results.solver.termination_condition == TerminationCondition.optimal
       
       # Validate binary decision variables (0 or 1)
       for w in model.Warehouses:
           assert model.y[w].value in [0.0, 1.0]
   ```

2. FOR MACHINE LEARNING / KAGGLE (tests/test_pipeline.py)
   ```python
   import pytest
   import pandas as pd
   import numpy as np
   from src.utils.data_loader import load_data
   from src.model.train import preprocess_features

   def test_pipeline_data_shapes():
       # Mock small dataset
       mock_data = pd.DataFrame({
           'LotArea': [1000, 2000, 1500],
           'SalePrice': [200000, 300000, 250000]
       })
       
       processed_x, processed_y = preprocess_features(mock_data)
       
       # Assertions to prevent data leakage and target misalignment
       assert processed_x.shape[0] == 3
       assert processed_y.shape[0] == 3
       assert not processed_x.isnull().values.any()
   ```

PART 4: JULES CI/CD GITHUB ACTIONS INTEGRATION
--------------------------------------------------------------------------------
To automate Jules, create `.github/workflows/jules-ci.yml` in your repo:
```yaml
name: Jules Quality Gateway
on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v3

      - name: Set up Python
        uses: actions/setup-python@v4
        with:
          python-version: '3.11'

      - name: Install system solvers
        run: |
          sudo apt-get update
          sudo apt-get install -y coinor-cbc glpk-utils

      - name: Install dependencies
        run: |
          python -m pip install --upgrade pip
          if [ -f requirements.txt ]; then pip install -r requirements.txt; fi

      - name: Run verification tests
        run: |
          pytest -v
```
